## 待完成與驗證限制

- 真實 API 僅在隔離 PostgreSQL schema 使用合成資料驗證，未載入個人資料。這證明本機憑證、模型權限及指定工具路徑可用，不代表每種自然語言說法都已評估；來源問答以可查核原文摘錄作答，沒有開放式模型摘要。
- 四道來源食譜可讀，但部分品牌、液體單位、罐頭瀝乾重量、蒜／油用量仍需實際資料。系統會要求澄清，不能宣稱全部食譜的個人實作營養已核實。
- 目前只有 S&B 咖哩與冷凍花椰菜核對 Walmart 商品頁與包裝數，其他品項連結明確缺漏。未驗證當地庫存，歷史價格不是即時售價。
- 配方步驟使用確認清單產生份量，保留原始全文供對照。鍋具容量、液體用量與最終熟度仍依實際條件確認。
- 尚未提供雲端網頁、正式 baseline、benchmark、安全評估或 iOS。這些是獨立後續里程碑。

## 開發預設與凍結界線

工具 schema 版本 v1.0，來源資料版本 v1.0；四份來源 PDF 及 USDA dataset 指紋見 `demo_data/source_manifest.json`。全套 104 項測試通過。每次客製化三輪，每回合 12 次模型／24 次工具，澄清三輪，模型 max_output_tokens=4096、timeout=45 秒，SDK 自動重試關閉。預設模型 gpt-6-luna、reasoning medium；真實回應 model ID、SDK 2.54.0 與 token 用量見 `live-api-result.json`。這是 V1 示範設定，尚未做課程 baseline 或成本／效能比較。

## 實作判斷紀錄

- 使用指定現有 checkout，未另建 worktree，沒有改動其他 repo 或 Obsidian。
- Skill 包裝腳本缺執行權限，採 bash／等價紀錄；未改動已安裝指引檔。
- 未知成本沒有可信上限，因此呈現已知小計與未知總額；不編造估算區間。
- 原始料理與估算保留，缺漏商品允許經使用者確認標示補齊，不把歷史每盒數字套到新配方。
- 規劃與確認由應用程式保存。未驗證模型自由文字不作為執行或達標依據，介面顯示服務結果與來源步驟。
- 同一回合重複的食用工具共用操作編號；若已提交後模型回覆中斷，介面允許一次取回已提交結果。下一個成功回合使用新編號，避免將一般重複輸入誤認為同一餐。
